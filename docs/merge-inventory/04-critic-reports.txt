== top_risks ==
 - Channel currency is never configured in code; a fresh database seeds every price in Vendure's default (USD) and the NEW frontend would display '$' while Mollie would charge in order.currencyCode — step 3 as drafted would not catch it because nobody checks the channel.
 - Placeholder 'sumup'/'paypal' methods (always eligible, offline invoice handler) are re-enabled on every boot; if any survive into the merged DB a customer can complete an order without paying.
 - Shipping is taxed at 25% (Swedish VAT residue, shipping.plugin.ts:25) and the NAVIL cart back-computes VAT from a NET subtotal — both produce wrong money figures and are treated as follow-ups or 'keep' in the draft plan.
 - Dashboard route overlays query fields absent from the NAVIL schema (virtual*, virtualProductCount, fitment, invoiceEmail/paymentTermsDays); orders, collections, product and customer admin pages are likely broken today and the plan keeps the dashboard package unchanged.
 - The draft plan's '/api path' instruction is wrong (code uses /shop-api); following the stale PROJECT-CONTEXT would break the client and the compose healthcheck.
 - Mollie is asynchronous (webhook to a public vendureHost) while the NEW checkout/confirmation is synchronous, non-idempotent and shows success unconditionally; without pending/failed handling, cart reset and a reachable webhook, orders will sit in ArrangingPayment and customers will see false confirmations.
 - German-primary and account-mandatory rules are contradicted by the NEW base (defaultLocale 'en', guest contact step, prefixed URLs, email deep links to non-existent routes) — silent regressions in SEO, verification and password-reset flows if step 2 does not address them.
 - B2B gating depends on customer groups named 'Privat'/'Företag' that nothing seeds and that the Bexio plugin ignores; invoice and business shipping silently disappear (or diverge from Bexio's company inference) after the rename.
 - Three incompatible deploy stories (konsoleH app.js, Docker §14 with a wrong healthcheck path, third-party pm2 workflow targeting an unknown host with git reset --hard) — copying the workflow could auto-deploy the merged code to a server the owner does not control.
 - Email transport 'none' without SendGrid plus Vendure's default requireVerification means registration, verification and password reset dead-end in every environment lacking the key; the plan's E2E cannot run locally without a dev mailbox.
 - NEW gql.tada schema and queries were generated from Vendure 3.7.0 without any custom fields; against 3.5.5 + CatalogPlugin + Mollie everything must be regenerated and every catalog/cart query extended — the 'keep NEW templates' step is larger than the plan implies, and search-driven listings need facets or tierKey queries because NAVIL seeds no facets.
 - /health is permanently 503 because CupsPlugin registers a health indicator unconditionally; any container/LB healthcheck on /health will flap or kill the service.
 - Two copies of brand-compatibility.json (backend data/, frontend src/data/) with 4 junk legend rows and no sync mechanism; the merged workspace needs one generated source or the picker and seeder will drift.
 - Docs (HANDOFF/PROJECT-CONTEXT/CLAUDE) contain at least 14 false statements (API path, Kustom, shipping, payments, prices, WoMo model, email transport, languages, plugin inventory, ports); 'merge into updated docs' without the correction list will re-introduce fixed bugs.
 - Fabricated content in the NEW base (tier feature ladders, 'GlobeGuard Camper', Renault SGW, testimonials, 'SGW Bypass Payload [INJECTED]' terminal, fake downloads/status) is spread across page.tsx, footer.tsx, home-interactive-sections.tsx, content/globeguard.ts and messages/*.json — a partial port leaks false claims that conflict with the owner's marketing guardrails.
