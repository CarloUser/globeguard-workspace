# GlobeGuard shop merge plan

Status: DRAFT for owner review, written 2026-09-17.
Basis: full read of both repo pairs by 9 parallel readers plus 2 critics (352 file reads). Raw output is in `docs/merge-inventory/`.
Sources: `Navil_gg_website/*` (CarloUser repos, authoritative business logic) and `New_globeguard_website/*` (Bilregistret repos, design/architecture donor only).

---

## 0. The decision in one paragraph

Backend = the Navil backend, cloned with history and cleaned. Frontend = the NEW frontend's App Router / Tailwind / shadcn shell and page architecture, emptied of its business content and refilled with Navil's domain logic, data, copy and pages. Kustom is removed and Mollie added. Nothing from the NEW backend is reused. Both source folders stay untouched as archives.

Guiding rules
1. Navil's business rules win everywhere they conflict with NEW. Where Navil's docs and Navil's code disagree, the code and the generated `data/*` files win (section 7 lists the stale doc statements).
2. Owner-approved facts only in copy (PROJECT-CONTEXT §11 marketing guardrails). Every NEW string that makes a business claim is replaced, not edited.
3. No hardcoded prices in the storefront. Teasers are derived from the catalogue.
4. One source for `brand-compatibility.json` (generated by the backend build script, copied to the frontend by the same script).
5. Money is displayed from Vendure's NET fields (`price`, `subTotal`, `taxSummary`, `shippingWithTax`). No back-computed VAT.

## 2. Facts found in the code that reshape the work

These were established by reading the code, not the docs. Each is cited in `docs/merge-inventory/`.

Backend (Navil)
- Kustom is already NOT registered. Residue: `src/plugins/kustom/` (6 files), `KUSTOM_*` typings in `environment.d.ts:34-42`, a `KUSTOM_FRONTEND_BASE_URL` alias in `vendure-config.ts:52-53`, and doc lines. `src/lib/customer-name-sanitizer.ts` is also used by DB subscribers and must stay.
- API paths are `/shop-api` and `/admin-api` (commit 2005329, 8 July). PROJECT-CONTEXT still says `/api`.
- Payment methods created on every boot: `invoice` (company customers only) plus `sumup` and `paypal`, which are placeholders wired to the offline invoice handler with an always-eligible checker. A customer can "pay" by card and get an authorised order with no money collected.
- Shipping methods are already Swiss/German (5 methods), but the calculator tax rate is hardcoded to 25 percent (Swedish VAT residue) and the methods are re-upserted on every boot, overwriting dashboard edits.
- Nothing sets the channel currency. A fresh database gets Vendure's default (USD) and every seeded price lands in it. Nothing seeds channel languages or triggers the search reindex either (documented as a manual admin step).
- Only country CH is seeded. No EU zone, no non-CH tax rates. Non-Swiss addresses are impossible on a fresh DB.
- B2B gating (invoice, business shipping, the `activeCustomerClassification` query) depends on customer groups literally named `Privat` and `Företag` that nothing creates. Bexio uses a different company signal (uid or VAT number, both non-public custom fields).
- Email: transport is `none` in every branch unless `SENDGRID_API_KEY` is set (the comment claiming console logging is false). Vendure's default `requireVerification: true` applies, and accounts are mandatory, so registration dead-ends locally. The header/footer partials reference 10 template variables that are never provided (every email ships with empty links), and the footer asserts "14 Tage Rückgaberecht" and "100% Kompatibel", which the guardrails forbid. Verify/reset links point to routes that exist in neither frontend.
- The dashboard is a 12 MB vendored copy of `@vendure/dashboard` 3.5.5 overlaid via Vite aliases. Seven overlaid route files still query fields the backend does not define (`virtualSku`, `virtualProductCount`, `productFitmentAdmin`, `invoiceEmail`, `paymentTermsDays`). Orders, collections, product and customer admin pages are expected to fail. `de.po` has 398 empty German entries; store-locator strings were never extracted.
- `car-lookup` is dead: Swedish plate regex, raw SQL against the `collectionModell` table that was deleted with virtual-products. Nothing GlobeGuard-side depends on it.
- CUPS registers a health indicator unconditionally, so `/health` is 503 wherever no CUPS server exists. No code prints labels today.
- Seeder bug: the `basic-womo` collection matcher targets the retired single SKU, so the 11 live WoMo products are in no collection. `brand-compatibility.json` has 81 entries of which 4 are Excel legend rows. Lamborghini is listed under the VAG licence in `extras.json` but has no SGW rule.
- Order codes are `SE` plus 5 random digits (Drivknuten prefix, 100k code space, stored in Bexio `api_reference`).
- Roughly 40 commits after 7 July 2026 in the Navil repos are by the same third-party developers who built the discarded NEW pair (API rename, deploy workflow, store locator, blog refactors, 24 `.po` rewrites, compose port 6544, frontend header refactor). The owner's last own commit is 7 July.
- Three deploy stories coexist: the documented Hetzner konsoleH supervisor (`deploy/app.js`, user drivkf), a Docker full stack (PROJECT-CONTEXT §14, healthcheck still on `/api`), and the third-party pm2 workflow (user `register`, `$HOME/apps/...`).
- Beta is live at driv.beta.globeguard.ch (233 products) and can serve as the image source via `scripts/sync-product-assets.mjs` once its default `/api` path is corrected. The V110 price sheet, product photos and manuals are not on this machine.

Frontend (Navil)
- All domain logic sits in one pure module (`src/services/globeguard-picker.ts`, 304 lines, depends only on `brand-compatibility.json`) plus `TierPicker.tsx` (372 lines), `ProductConfigurator.tsx` (1017 lines) and the Redux thunk `cartAddConfiguredItems`. The configuration travels only in the product URL (`?year=YYYY&extraBrands=id:year,id`).
- Cart totals are wrong under the NET rule: `cartDisplayTotals.ts` treats the NET subtotal as VAT-inclusive and back-computes an "Inkl. MwSt." row. Add-on quantities do not scale with device quantity. The add is N+1 sequential mutations with no rollback.
- The auth "gate" checks a localStorage `customerToken`, which is actually the channel token from `login.channels[0].token`; the real session is the cookie. Not a rule to port.
- The Kustom checkout path is a dead loop; only the invoice path works. `/cart/checkout/[token]` is a generic success page.
- Hardcoded "ab CHF" teasers disagree between pages (620/820 vs 583/790/1'980).
- `typescript.ignoreBuildErrors: true` hides latent errors (e.g. an undefined `GLOBEGUARD_HEADER_MENU`).
- Legal/about pages are Swedish Drivknuten text, terms is lorem ipsum, FAQ is lorem ipsum not wired to the FAQ plugin, robots.txt advertises drivknuten.se, JSON-LD has `areaServed: SE`.

Frontend (NEW)
- Fork of Vendure GmbH's official Next.js starter (MIT). Tokens are already GlobeGuard-branded (#0083C2 / #0E1E4B / #4594E1) but dozens of components use off-token hex from an earlier teal theme and 37 non-existent Tailwind shades (`slate-250`, `slate-405` ...).
- `defaultLocale: 'en'` with always-prefixed URLs; de maps to `de-DE`. Navil/old site are German at the root, `/en/` prefixed, `de-CH` formatting.
- No navigation renders between 768 and 1279 px (desktop nav `xl:flex`, mobile trigger `md:hidden` inside `xl:hidden`). Hover-only dropdowns. Favicon in the wrong folder. Google Fonts CSS import plus redundant Geist.
- Guest checkout is assumed (contact step, `setCustomerForOrder`). Real multi-currency switching (`?currencyCode=` on every call, cookie, Price defaults to EUR, delivery step hardcodes USD). Everything shows `priceWithTax` under an "excl. VAT" label. Country default US. No billing address form. `placeOrder` is synchronous and non-idempotent; confirmation always shows success.
- Add-to-cart has no order-line customFields and no multi-line add; product cards add to cart directly (bypasses brand/year configuration).
- `graphql-env.d.ts` was introspected from stock Vendure 3.7.0 without any custom fields; `GetTopCollectionsQuery` returns every non-root collection; no facets exist on the Navil side so the facet sidebar would be empty; product classification is regex over product names.
- Wrong or fabricated business content is spread across `page.tsx` (inline `homeCopy`), `footer.tsx`, `home-interactive-sections.tsx`, `content/globeguard.ts`, `product-detail-tabs.tsx`, `vin-checker.tsx`, `compatibility-wizard.tsx`, `messages/*.json` (tier feature ladders, "GlobeGuard Camper", Renault SGW, three invented testimonials, a fake "SGW Bypass Payload [INJECTED]" terminal, fake status indicator, non-existent downloads, 2026 trade shows, Caterpillar/John Deere/Putzmeister in the brand list). AI-rendered device images with Midjourney prompts in the code. 11 mojibake German strings.
- Cache helpers do not cache; `/api/revalidate` tags match no query. Auth cookie has no httpOnly/secure/sameSite; logout does not send the token.
- Solid and worth keeping: layout/token system, shadcn primitives, product/collection/search templates, cart, the checkout step machine, account area, all auth flows, metadata helpers, robots, health route, server-only Vendure client with bearer token forwarding (this is the correct auth mechanism for the Navil backend, which enables bearer and cookie).
